금융 데이터로 만드는 n8n 자동화 5안

n8n 중심 Agent 교육(8시간 × 7회)을 마친 금융사 교육생 5명이 마지막 하루(8시간) 안에 완성할 수 있는 범위로 설계했습니다. 교육장에서는 회사 실데이터를 쓰기 어렵다고 보고, 모든 안이 공공 Open API의 실데이터나 가상 데이터를 씁니다. 예시 주제들이 뉴스·규제·RAG·OCR처럼 텍스트 요약·검색 중심이라, 이 기획안들은 데이터를 수집·검증·분석하거나 텍스트를 정형 데이터로 바꾸는 쪽으로 차별화했습니다.

확인된 기술 포인트

n8n의 전용 SQL Agent는 1.82.0부터 지원 중단(deprecated)됐고 3.0에서 제거됩니다. 그래서 AI Agent(Tools Agent)에 Postgres 노드를 툴로 붙이는 방식으로 설계했습니다. Guardrails의 PII 목록에는 국내 주민등록번호 같은 식별자가 없을 수 있으니 Custom Regex로 직접 추가하세요.

보안

1차 방어선은 SELECT만 가능한 DB 계정입니다. 프롬프트 지시만으로는 쓰기 쿼리를 막을 수 없습니다. 민감한 컬럼은 마스킹된 뷰로만 보여주세요.

워크플로우

  1. n8n Form

    제출 부서, 기준월, 파일(File 필드) 입력

  2. Extract From File

    CSV·XLSX를 행 단위 항목으로 변환

  3. Data Table

    코드 마스터와 전월 확정 데이터 조회

  4. Code

    규칙 검사 → 오류 목록 {행, 컬럼, 규칙, 값, 심각도}

  5. SummarizeAI Agent

    규칙별·심각도별 건수를 집계하고, 오류 목록만 근거로 제출자용 수정 안내문 작성

  6. SwitchForm Ending

    결과별로 분기하고 제출 화면에 바로 응답

    • 오류 Convert to File(XLSX) → Form Ending의 Return Binary File로 오류 리포트를 바로 내려받게 함
    • 경고만 승인 서브 워크플로우를 완료 대기 없이 실행하고, “담당자 확인 후 메일 안내” 화면 표시
    • 통과 Data Table에 확정 데이터로 적재하고 제출 완료 화면 표시
  7. Execute Sub-workflowSlackGmail

    승인 서브 워크플로우: Slack Send and Wait for Response(Approval)로 담당자 승인 → 승인 시 적재, 결과를 제출자에게 메일로 회신

핵심 원칙

통과·반려 판정은 Code 노드의 규칙이 하고, AI는 오류 목록을 읽기 쉬운 안내문으로 바꾸는 일만 합니다. 외부 공공 API가 필요 없어서 망분리 환경에서도 진행하기 쉽습니다. LLM 접속은 필요합니다.

병렬로 개발하기

각자 서브 워크플로우를 맡고, 앞단 결과는 Pin data로 고정해서 서로 기다리지 않습니다. 통합은 Execute Sub-workflow로 연결하고 Error Trigger로 오류를 받습니다.

숫자 정확성

수치는 HTTP Request·Code·Summarize 노드가 만들고, LLM은 그 수치를 인용·해설만 합니다. 프롬프트에 “제공된 값 외 수치 생성 금지”를 명시하세요.

키와 저장소

API 키는 URL에 넣지 말고 Credentials(Query Auth)로 관리하세요. Data Table은 인스턴스 전체 기본 200MiB 한도이고, Code 노드에서는 직접 읽을 수 없어 Data Table 노드로 다뤄야 합니다.
